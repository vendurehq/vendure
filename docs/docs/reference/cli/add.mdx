<a name="add-api-extension"></a>

## vendure add api-extension

Add an Admin API extension to a plugin, with a resolver that calls a service.

```bash
vendure add api-extension [options]
```

- **Behavior:** `mutating`. Changes files, the database or the dev server.
- **Developer MCP tool:** `add_api-extension`

### Options

| Option | Type | Description |
| ------ | ---- | ----------- |
| `--plugin <plugin>` | string | Required. The name of the plugin class. The valid values depend on the project, and an `input` need lists them. |
| `--service <service>` | string | Required. The service the resolver calls. A CRUD service of an entity gets the full CRUD API. The valid values depend on the project, and an `input` need lists them. |
| `--query-name <query-name>` | string | The name of a query to add. Not used for a CRUD service. |
| `--mutation-name <mutation-name>` | string | The name of a mutation to add. Not used for a CRUD service. |

### Output

| Field | Type | Description |
| ----- | ---- | ----------- |
| `plugin` | string |  |
| `service` | string |  |
| `resolver` | string |  |
| `crud` | boolean | True when the service is a CRUD service of an entity. |
| `modifiedFiles` | array of string |  |

### Errors

- `add.plugin-not-found` (exit code 1)
- `add.plugin-ambiguous` (exit code 1)
- `add.service-not-found` (exit code 1)
- `add.api-extension-failed` (exit code 1)

### Examples

```bash
vendure add api-extension --plugin ReviewsPlugin --service ReviewService --query-name reviews
vendure add api-extension --plugin ReviewsPlugin --service ProductReviewService
```

## vendure add entity

Add a new entity to a plugin.

```bash

```

- **Developer MCP tool:** `add_entity`

### Options

| Option | Type | Description |
| ------ | ---- | ----------- |
| `[name]`, `--name <name>` | string | Required. The name of the entity class, in PascalCase, for example ProductReview. |

| Field | Type | Description |
| ----- | ---- | ----------- |
| `entity` | string |  |

- `add.plugin-ambiguous` (exit code 1)

### Examples


<a name="add-plugin"></a>

## vendure add plugin

Create a new Vendure plugin and add it to the Vendure config.

```bash
vendure add plugin [name] [options]
```

- **Behavior:** `mutating`. Changes files, the database or the dev server.
- **Developer MCP tool:** `add_plugin`

### Options

| Option | Type | Description |
| ------ | ---- | ----------- |
| `[name]`, `--name <name>` | string | Required. The name of the plugin, for example reviews. The class is named ReviewsPlugin. |
| `--dir <dir>` | string | The directory of the plugin. Leave it empty for a directory next to the existing plugins, or src/plugins. Asked for in an interactive terminal. |
| `--config <config>` | string | The path to a custom Vendure config file. |

### Output

| Field | Type | Description |
| ----- | ---- | ----------- |
| `plugin` | string | The name of the plugin class. |
| `dir` | string |  |
| `modifiedFiles` | array of string |  |

### Errors

- `add.file-exists` (exit code 1)
- `add.vendure-config-not-found` (exit code 1)

### Examples

```bash
vendure add plugin reviews
vendure add plugin reviews --dir ./src/plugins/reviews
```
