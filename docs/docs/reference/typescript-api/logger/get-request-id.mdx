Returns the ID of the API request which the current code is running for, or `undefined` outside
a request.

Every request gets an ID. It is taken from the `x-request-id` request header when that is a short
string of safe characters (letters, digits, `.`, `_`, `:` and `-`, at most 128 of them), and is
otherwise generated. The response returns it in the `x-request-id` header. Accepting an inbound
ID lets a proxy or a client trace one request across several services. The inbound value is
chosen by the caller, so it identifies log lines but must not be used for security decisions.

While a worker processes a [Job](/reference/typescript-api/job-queue/job#job), this returns the ID of the request which added the job.
The same ID is available as `ctx.requestId` on the [RequestContext](/reference/typescript-api/request/request-context#requestcontext). A custom
[VendureLogger](/reference/typescript-api/logger/vendure-logger#vendurelogger) can call this function to add the ID to its log lines.

*Example*

```ts
import { getRequestId, VendureLogger } from '@vendure/core';

export class MyLogger implements VendureLogger {
    info(message: string, context?: string) {
        myLogService.write({ level: 'info', message, context, requestId: getRequestId() });
    }
    // ...
}
```
