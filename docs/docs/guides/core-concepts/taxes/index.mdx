E-commerce applications need to correctly handle taxes such as sales tax or value added tax (VAT). In Vendure, tax handling consists of:

* **Tax categories** Each ProductVariant is assigned to a specific TaxCategory. In some tax systems, the tax rate differs depending on the type of good. For example, VAT in the UK has 3 rates, "standard" (most goods), "reduced" (e.g. child car seats) and "zero" (e.g. books).
* **Tax rates** This is the tax rate applied to a specific tax category for a specific [Zone](/core-concepts/zones/). E.g., the tax rate for "standard" goods in the UK Zone is 20%.
* **Channel tax settings** Each Channel can specify whether the prices of product variants are inclusive of tax or not, and also specify the default Zone to use for tax calculations.
* **TaxZoneStrategy** Determines the active tax Zone used when calculating what TaxRate to apply. By default, it uses the default tax Zone from the Channel settings.
* **TaxLineCalculationStrategy** This determines the taxes applied when adding an item to an Order. If you want to integrate a 3rd-party tax API or other async lookup, this is where it would be done.

## API conventions

In the GraphQL API, any type which has a taxable price will split that price into two fields: `price` and `priceWithTax`. This pattern also holds for other price fields, e.g.

```graphql
query {
  activeOrder {
    ...on Order {
      lines {
        linePrice
        linePriceWithTax
      }
      subTotal
      subTotalWithTax
      shipping
      shippingWithTax
      total
      totalWithTax
    }
  }
}
```

In your storefront, you can therefore choose whether to display the prices with or without tax, according to the laws and conventions of the area in which your business operates.

## Calculating tax on order lines

When a customer adds an item to the Order, the following logic takes place:

1. The price of the item, and whether that price is inclusive of tax, is determined according to the configured [OrderItemPriceCalculationStrategy](/reference/typescript-api/orders/order-item-price-calculation-strategy/).
2. The active tax Zone is determined based on the configured [TaxZoneStrategy](/reference/typescript-api/tax/tax-zone-strategy/). By default, Vendure will use the default tax Zone from the Channel settings.
  However, you often want to use the customer's address as the basis for determining the tax Zone. In this case, you should use the [AddressBasedTaxZoneStrategy](/reference/typescript-api/tax/address-based-tax-zone-strategy).
3. The applicable TaxRate is fetched based on the ProductVariant's TaxCategory and the active tax Zone determined in step 1.
4. The `TaxLineCalculationStrategy.calculate()` of the configured [TaxLineCalculationStrategy](/reference/typescript-api/tax/tax-line-calculation-strategy/) is called, which will return one or more [TaxLines](/reference/graphql-api/admin/object-types/#taxline).
5. The final `priceWithTax` of the order line is calculated based on all the above.

### Tax amounts from an external system

By default, Vendure derives the tax of an order line from the rates of its TaxLines. An external system such as an ERP may calculate the tax with its own rounding, for example rounding a tax of 199.4875 to 199.50 rather than 199.49. If the tax in Vendure must match it exactly, return the external system's result as the `amount` of each TaxLine from your TaxLineCalculationStrategy:

```ts
import { CalculateTaxLinesArgs, TaxLineCalculationStrategy } from '@vendure/core';

export class ErpTaxLineCalculationStrategy implements TaxLineCalculationStrategy {
    async calculate({ orderLine, applicableTaxRate }: CalculateTaxLinesArgs) {
        const lineTotal = orderLine.listPriceIncludesTax
            ? orderLine.proratedLinePriceWithTax
            : orderLine.proratedLinePrice;
        const erpTax = await erpClient.getLineTax(orderLine.productVariant.sku, lineTotal);
        return [
            {
                description: applicableTaxRate.name,
                taxRate: applicableTaxRate.value,
                amount: erpTax.amountInCents,
            },
        ];
    }
}
```

The `amount` is the tax of the whole line, as an integer in minor units. It applies to the line total in the tax basis of the line's price: the net total when prices exclude tax, and the gross total when they include it. Set it on all or none of a line's TaxLines.

The line's tax, the Order totals and the tax summary then use the amount, with both the default `OrderTaxCalculationStrategy` and the `OrderLevelTaxCalculationStrategy`. The `taxRate` remains the rate that the line displays. After a partial cancellation, the remaining units get their share of the amount, and refunds add up to exactly what was paid.

For shipping lines and surcharges, implement the optional `calculateShippingLineTaxLines()` and `calculateSurchargeTaxLines()` methods in the same way. Vendure calls them after the shipping price and shipping promotions are applied. Without them, shipping and surcharges derive their tax from the rate.

#### When Vendure asks again

- `calculate()` is called per order line. Cache the external system's answer for the whole order for the duration of a request, so that one request to it serves all the lines.
- In a cart, when a line is added, removed or repriced, Vendure asks again about every line, shipping line and surcharge with an amount. An external system that rounds the tax on the order total may move a rounding difference from one line to another, so the amounts of the unchanged lines can change too.
- When no line changed, for example when only the shipping method changed, the lines keep their amounts and Vendure does not ask about them again. A shipping line or surcharge is asked again only when its own price changed.
- On a placed order, an unchanged line keeps the amount that was paid, even if the external system would answer differently today. To replace the amounts, for example after a change of address, use the `recalculateTax` option of `modifyOrder`, with `dryRun` first to see the result. The Dashboard offers it on the order modification page.

#### Promotions see the rate

Promotions and their conditions judge the order on the tax that the rates give, and the external system's amounts are applied afterwards. Otherwise a promotion whose tax-inclusive threshold sits within a cent of the order total could switch on and off on every recalculation. Shipping, and the shipping eligibility checks, see the external system's amounts.

#### When the external system is unavailable

If your strategy cannot reach the external system, it can either throw an error, which makes the cart operation fail, or return TaxLines without an `amount`, so that the tax comes from the rate. To keep a customer from paying an estimated tax, refuse the transition to `ArrangingPayment` in a custom [OrderProcess](/reference/typescript-api/orders/order-process/) while any line has an `amount` of `null`. A null `amount` means that the strategy provided none. A stored amount that was rescaled after a cancellation still has a value.

## Calculating tax on shipping

The taxes on shipping is calculated by the [ShippingCalculator](/reference/typescript-api/shipping/shipping-calculator/) of the Order's selected [ShippingMethod](/reference/typescript-api/entities/shipping-method/).

## Code Examples

### Default tax configuration

This example shows the default configuration for taxes (you don't need to specify this in your own config, as these are the defaults):

```ts title="src/vendure-config.ts"
import {
    DefaultTaxLineCalculationStrategy,
    DefaultTaxZoneStrategy,
    DefaultOrderItemPriceCalculationStrategy,
    VendureConfig
} from '@vendure/core';

export const config: VendureConfig = {
  taxOptions: {
    taxZoneStrategy: new DefaultTaxZoneStrategy(),
    taxLineCalculationStrategy: new DefaultTaxLineCalculationStrategy(),
  },
  orderOptions: {
    orderItemPriceCalculationStrategy: new DefaultOrderItemPriceCalculationStrategy()
  }
}
```
