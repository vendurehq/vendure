This page lists the v4 changes to the Shop API, and to the server defaults, that affect storefronts.

## Role assignments

Single-channel storefronts are not affected. Where Customers use more than one Channel:

- A Customer holds `Authenticated` only on the Channels they are a member of. With the default `CustomerChannelAssignmentStrategy` nothing changes for the shopper. With a strategy that declines the assignment, `me` fails with a `ForbiddenError` on that Channel, `activeCustomer` returns `null`, and `setCustomerForOrder` returns an `AlreadyLoggedInError`.
- `CurrentUser.channels`, returned by `login`, `authenticate` and `me`, lists only the Channels the Customer is a member of.

For details, see [Storefront changes](/developer-guide/migrating-from-v3/role-assignments#storefront-changes).

## CORS and CSRF prevention

Two server defaults changed, and both can stop a storefront from reaching the Shop API:

- `apiOptions.cors` no longer allows cross-origin requests. A storefront that calls the Shop API from the browser on a different origin, including another port on `localhost`, gets a CORS error until its origin is listed in `apiOptions.cors.origin`. Requests from a server, such as server-side rendering, are not affected.
- `apiOptions.csrfPrevention` is on. A storefront that sends queries as `GET`, for example to cache them, must send an `Apollo-Require-Preflight: true` header. Requests sent as `POST` with `application/json` are not affected.

For details, see [Changed defaults](/developer-guide/migrating-from-v3/breaking-api-changes#cors-allows-no-cross-origin-requests).

## Removed deprecated fields

These Shop API fields were deprecated during v3 and are removed in v4:

| Removed | Use instead |
|---|---|
| `SearchInput.facetValueIds` and `SearchInput.facetValueOperator` | `SearchInput.facetValueFilters`. `facetValueIds: [a, b]` with `AND` becomes `[{ and: a }, { and: b }]`; with `OR` it becomes `[{ or: [a, b] }]`. |
| `Channel.currencyCode` | `Channel.defaultCurrencyCode` |
| `Fulfillment.summary` | `Fulfillment.lines` |
