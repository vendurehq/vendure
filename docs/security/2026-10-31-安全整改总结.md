## 3. 修复项详情

### 3.1 S1：40 个 admin 接口权限映射

涉及 4 个 resolver（审计口径 40 个接口；提交 diff 新增 51 条 `@Allow` 装饰器，含同一接口的多权限组合）：

| 插件 / resolver | 映射规则 |
| --- | --- |
| `distribution-plugin`（8 条） | 分销商 / 佣金查询 → `ReadCustomer \| SuperAdmin`；提现列表与提现审批、驳回、标记已付 → 仅 `SuperAdmin`（资金类收紧） |
| `operations-plugin` marketing（10 条） | 营销位 / 推荐 / 公告等读写 → 对应 `Manage*` 权限 `\| SuperAdmin` |
| `payment-schedule-plugin`（7 条） | 计划查询 → `ReadOrder \| SuperAdmin`；写操作先收敛为 `UpdateOrder \| SuperAdmin`，随后改为 `ManagePaymentSchedule \| SuperAdmin` |
| `tcm-clinic-plugin`（26 条） | 读 → `ReadCustomer \| SuperAdmin`；建馆 / 绑定员工 → 仅 `SuperAdmin`；业务写 → `UpdateCustomer \| SuperAdmin` 且叠加馆归属守卫 |

**验证证据**
- 匿名调用：修复前可返回管理数据；修复后统一 `FORBIDDEN`。
- 合法 token：superadmin 全量可用；店长在授权接口可用。
- 生产冒烟：`admin-api` 匿名 `me` 返回 `FORBIDDEN`；`shop-api` 商品查询正常（`totalItems = 54`）。

### 3.2 ManagePaymentSchedule 自定义权限与 role-sync

- 新增 `PermissionDefinition('ManagePaymentSchedule')`，语义限定为「确认 COD 收款 / 释放租赁押金 / 开尾款窗口 / 确认卖家违约」，刻意不复用 `UpdateOrder`，避免顺带放开改单改价。
- 权限注册于 `payment-schedule-plugin/src/plugin.ts`，resolver 写接口使用 `@Allow(ManagePaymentSchedule, SuperAdmin)`。
- `delivery-plugin` 在 bootstrap 阶段执行 `RoleSyncService.syncRoles()`：从 `ROLE_PERMISSIONS_MAP` 为 `manager` / `super-admin` 增量补绑缺失权限，不删除既有自定义权限。
- e2e 覆盖店长可释放租赁押金 / 确认 COD，只读角色与匿名被拒。

### 3.3 TCM 读 / 写 clinicId 隔离规则

**读路径**
- 从当前管理员的员工绑定解析可读馆集合；SuperAdmin 跨馆全量；未绑定任何馆返回空结果。
- 指定 `clinicId` 的查询先执行 `assertCanReadClinic`，非本馆员工抛 Forbidden。
- 审计日志无 `clinicId`，按「可读馆在职员工」的 `staffId` 过滤。

**写路径**
- 统一 `assertCanWriteClinic`：SuperAdmin 可写全量（未绑定时审计 `staffId` 以 0 兜底）；普通账号必须绑定目标馆。
- 未绑定任何诊所 → `error.tcm-account-not-bound`；有绑定但不属于目标馆 → `error.tcm-clinic-access-denied`。
- 更新 / 删除按记录「当前所属馆」校验，不信任入参 `clinicId`，防止「传本馆 id 改他馆记录」。
- 患者档案跨馆共享时，非 SuperAdmin 不允许把他馆档案带入本馆接诊。

### 3.4 前端未绑定诊所空态（tcm-workbench）

- 新增 `components/NotBoundClinic.vue` 与 `composables/useClinicBinding.ts`。
- 首页、接诊、记录、计划、随访等页面在 `myStaff` 为空时，展示「未绑定诊所」引导（含申请绑定入口），替代通用「暂无数据」空列表。
- 提交 `fbbee82`，附 4 张空态截图；该仓库独立构建发布，不随 vendure 部署。

### 3.5 runScheduleScan 与团购渠道过滤

**runScheduleScan**
- 权限从 `UpdateOrder | SuperAdmin` 收敛为 `ManagePaymentSchedule | SuperAdmin`，向店长开放。
- 服务端 `processTriggers` / `processOverdue` / `processShipDeadlines` 全部基于 `ctx.channelId` 取数，手动触发只等价于「提前执行本渠道的每分钟任务」，无跨渠道副作用。
- 定时任务 `PaymentScheduleJob.runAllChannels` 逐渠道新建上下文，不经过 resolver `@Allow`，权限调整不影响定时路径。

**failSchedulesForGroupBuy**
- 先取当前渠道的计划 id，再对团购期次逐条 `isScheduleInChannel` 过滤，避免跨渠道退款 / 状态变更。

**handleGroupBuyCompleted（事件入口）**
- 不依赖事件侧可能缺失的 `ctx.channelId`，改为读取活动自身 `channels` 关联。
- 活动关联渠道数不为 1 时记录 warn 并直接返回 0，不做任何写入。
- 仅对属于该渠道的期次执行 `locked → payable` 与尾款通知；同渠道正常流转不变。
- e2e 构造渠道 2 的活动与期次，只触发该活动：渠道 2 期次解锁，渠道 1 期次保持 `locked`；随后触发渠道 1 活动正常解锁。

**e2e 结果（本次复跑）**
- `payment-schedule-plugin`：10 / 10 passed。
- `tcm-clinic-plugin`：11 / 11 passed（含读隔离、写隔离两条）。
- `rental-plugin`：新增 1 条店长释放押金权限门禁用例（随 `eaa450c4c` 合入）。
